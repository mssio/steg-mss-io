# steg.mss.io v2 (client-side React + WASM) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static React site where a Rust/WASM core hides and reveals password-encrypted messages in PNG/JPEG photos entirely in the browser.

**Architecture:** `crates/steg-core` (pure Rust, native-testable) holds image I/O, Hamming ECC, block embedding and format-v1 crypto; thin `wasm-bindgen` exports sit in `lib.rs`. wasm-pack output lands in `src/wasm/` and is loaded by a module Web Worker; `src/lib/steg-client.ts` wraps it in typed promises. The Vite + React 19 UI (Tailwind v4, shadcn, React Router v7) is designed from scratch to the darkroom concept and builds to a host-neutral static `dist/` (config shipped for Cloudflare and Vercel).

**Tech Stack:** Rust (`image` 0.25 png+jpeg, `rand_chacha`, `sha2`, `pbkdf2`, `hkdf`, `aes-gcm`, `getrandom`, `wasm-bindgen`), wasm-pack; Bun, Vite 8, React 19, TypeScript, Tailwind v4, shadcn/ui, React Router v7, sonner, lucide-react, fontsource; `@resvg/resvg-js`; Cloudflare Workers static assets (`wrangler`) / Vercel configs.

**Spec:** `docs/superpowers/specs/2026-11-20-steg-wasm-design.md` (restates `../docs/steg-wasm-brief.md`). Read it before every task; section numbers below (§) refer to it.

## Global Constraints

- Never modify `public/hero.webp`, `public/og-art.png`, `public/samples/*.jpg`.
- Copy nothing from the old frontend; port (don't copy) logic from `../reference/steg-api-mss-io/scripts/text-image-advance.py` (`RobustBlockSteg` only).
- No `console.*` (or any logging) of message, password or image data, in Rust or TS.
- Format v1 constants: version `0x01`; salt 16 B; nonce 12 B; tag 16 B; PBKDF2-HMAC-SHA256 600_000 iterations, 32 B; HKDF-SHA256 infos `"steg-mss-io/v1/order"`, `"steg-mss-io/v1/aes"`; header seed `SHA-256("steg-mss-io/v1/header")`; AAD = `version || salt`.
- Embedding constants: block 8×8, centre = rows/cols 2..6, strength S = 25, redundancy 3, Hamming(7,4) codeword `p1 p2 d1 p3 d2 d3 d4`, bits MSB first, `Y = 0.299R + 0.587G + 0.114B`; header = 714 blocks; length field = first 84 body blocks.
- Limits: 500 code points; 40_000_000 pixels; output JPEG quality 92.
- Exact user-facing error strings (Rust is the source of truth; UI shows them as-is):
  - `No message found, or the password is wrong.`
  - `Image is too large (max 40 megapixels).`
  - `Only PNG and JPEG images are supported.`
  - `This image is too small to hold a message.`
  - `This image can hold at most {N} characters.`
  - `Enter a message.` / `Enter a password.`
- Passwords are used exactly as typed (no trimming, no normalisation).
- No Docker, no nginx, no server code. CSP (§10) must hold in production: no inline scripts, no third-party origins.
- All work happens on the feature branch `feat/client-side-wasm`; never commit to `main`. Merging is the owner's call.
- Commit after each milestone with the attribution line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Smaller per-task commits are fine.
- **Hard stop after Task 8** for the owner's UI review.

## Review Focus

1. **Odd image formats** (RGBA PNG, 16-bit PNG, grayscale JPEG, CMYK JPEG) → decode to RGB8 and round-trip; WebP/HEIC/GIF → `Only PNG and JPEG images are supported.` Test in Task 2.
2. **Dimensions not divisible by 8** (e.g. 1003×757) → edge pixels untouched, round trip works. Test in Task 4.
3. **Revealing an image that never had a message** (an untouched sample photo) → generic error, no panic, no big allocation. Test in Task 4.
4. **Stale results:** the user swaps the image or switches Hide/Reveal while the worker is busy → the late result is dropped, never shown against the new image; the primary button is disabled while busy (no double submit). Pinned by a run-generation check, tested in Task 7 and checked by hand in Task 9.
5. **Password edge cases:** non-ASCII passwords round-trip; `" pass"` and `"pass"` are different passwords. Test in Task 4.

### Task 3: Block orders and the embedding encoder

**Files:**
- Create: `crates/steg-core/src/blocks.rs`, `crates/steg-core/tests/blocks.rs`

**Interfaces:**
- Consumes: `ecc::*`, `image::RgbImage`.
- Produces:
  - `pub struct Grid { pub bw: u32, pub bh: u32 }` with `fn from_dims(w,h)`, `fn total(&self) -> usize`.
  - `pub const HEADER_BLOCKS: usize = 714;`
  - `pub fn header_order(total: usize) -> Vec<u32>` (first 714 of the public shuffle)
  - `pub fn body_order(total: usize, header: &[u32], seed: [u8; 32]) -> Vec<u32>` (remaining blocks ascending, then shuffled)
  - `pub fn shuffle(v: &mut [u32], rng: &mut ChaCha20Rng)` — hand-written Fisher–Yates, below.
  - `pub enum Encoder { Python, Adjusted, AdjustedCap(f32), AdjustedMargin(f32) }`; `pub const DEFAULT_ENCODER: Encoder` (set from Task 5's result; `Adjusted` until then).
  - `pub fn embed(px: &mut [f32], grid: &Grid, width: u32, order: &[u32], coded: &[u8], enc: Encoder)` — `px` is interleaved RGB f32; each coded bit occupies `REDUNDANCY` consecutive entries of `order`.
  - `pub fn read_bits(rgb: &RgbImage, grid: &Grid, order: &[u32], n_coded: usize) -> Vec<u8>` — majority over 3 consecutive blocks.
  - `pub fn block_diff(...)`: centre-minus-edge mean Y of one block (shared by embed and read).

Fisher–Yates (determined here so orders never depend on `rand` internals):
```rust
for i in (1..v.len()).rev() {
    let n = (i + 1) as u64;
    let zone = u64::MAX - (u64::MAX % n);   // reject to avoid modulo bias
    let j = loop { let r = rng.next_u64(); if r < zone { break (r % n) as usize } };
    v.swap(i, j);
}
```
Adjusted encoder per block (§6.4): `d = block_diff`; `t = ±S` (× margin for `AdjustedMargin`); `o = if d.signum()==t.signum() { t } else { t - d }`, capped at `|o| ≤ cap·S` for `AdjustedCap`; centre `+= o/2`, edge `-= o/2` in R,G,B; then clamp to [0,255] and, if the clamped diff falls short of `t`, push the region that still has headroom by the shortfall (once) and clamp again. `Python` = always `o = t`, no compensation.

- [ ] **Step 1: Write failing tests in `tests/blocks.rs`:**

  - `header_and_body_disjoint`: for total = 48_896 the union of `header_order` and `body_order(.., seed)` has no duplicates and covers every block.
  - `body_order_depends_on_seed_only`: different seeds → different orders; same seed → identical; header unchanged.
  - `shuffle_golden`: shuffle `0..10` with `ChaCha20Rng::from_seed([7;32])` equals a hard-coded vector (record it on first green run; it guards platform/version drift).
